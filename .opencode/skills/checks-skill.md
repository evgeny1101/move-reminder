# Skill: Проверка проекта

Этот скилл описывает, как AI-агенту выполнять проверки после изменений в `move-reminder`.

## Когда использовать

- Любое изменение Python-кода (`timer_tray.py`, тесты, вспомогательные модули).
- Любое изменение скриптов запуска/окружения (`run.sh`, `setup_dev.sh`, `debian/move-reminder-launcher`).
- Любое изменение desktop-файлов (`move-reminder.desktop`, `debian/move-reminder.desktop`).

## Цель

- Подтвердить, что код корректен синтаксически.
- Подтвердить, что линтер и тесты проходят.
- Не пропустить регрессии в пользовательском сценарии таймера в трее.

## Порядок проверок

1. Убедиться, что используется venv из проекта.
2. Запустить статические проверки Python.
3. Запустить тесты.
4. Запустить проверки shell/desktop (если затронуты соответствующие файлы; можно запускать всегда).
5. Для изменений поведения таймера выполнить ручной smoke-check в GNOME.

## Команды

Запускать из корня проекта:

```bash
.venv/bin/ruff check .
.venv/bin/pytest -q
.venv/bin/python -m py_compile timer_tray.py
bash -n run.sh
bash -n setup_dev.sh
bash -n debian/move-reminder-launcher
desktop-file-validate move-reminder.desktop
desktop-file-validate debian/move-reminder.desktop
```

## Ручной smoke-check (обязательно для UI/таймера)

1. Запустить `./run.sh`.
2. Проверить, что появился значок в трее.
3. Запустить таймер на короткое время (1 минута или меньше через ожидание).
4. Проверить завершение отсчета, уведомление и звук (если аудио доступно в системе).
5. Проверить single-instance: повторный запуск не создает второй экземпляр.

## Правила для тестов при добавлении функционала

- При добавлении новой логики добавлять/обновлять `pytest`-тесты в `tests/`.
- Для bugfix сначала добавить тест, который воспроизводит баг, затем исправление.
- Для логики, зависящей от GTK/`gi`, по возможности тестировать изолированно через моки/стабы.
- Если тест невозможно автоматизировать адекватно, явно фиксировать шаги ручной проверки в описании изменений.

## Критерий готовности

- `ruff`, `pytest`, `py_compile` проходят.
- Связанные shell/desktop проверки проходят.
- Для UI-поведения выполнен ручной smoke-check и результат зафиксирован в отчете.
