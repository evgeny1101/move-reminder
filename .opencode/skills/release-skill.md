# Skill: Подготовка и выпуск релиза

Этот скилл описывает безопасный порядок выпуска новой версии `move-reminder`.

## Когда использовать

- При подготовке любого релиза (`vX.Y.Z`).
- При обновлении `CHANGELOG.md`, версии Debian-пакета и релизного тега.

## Цель

- Выпустить согласованный релиз приложения и Debian-пакета.
- Избежать расхождения версий между git-тегом, `CHANGELOG.md` и `debian/changelog`.
- Гарантировать, что в релиз попадает только проверенный код.

## Правила версионирования

- Git-тег приложения: `vX.Y.Z` (например, `v1.0.0`).
- Debian-версия: `X.Y.Z-1` для первого Debian-релиза этой версии приложения.
- Если меняется только пакетирование Debian без изменения кода приложения:
  - использовать `X.Y.Z-2`, `X.Y.Z-3` и т.д.
- Для первой стабильной версии использовать `v1.0.0` и `1.0.0-1`.

## Последовательность релиза (обязательная)

1. Проверить рабочее дерево и синхронизацию с `origin/master`.
2. Обновить `CHANGELOG.md` по изменениям с прошлого релиза.
3. Обновить `debian/changelog` до новой версии `X.Y.Z-1`.
4. Закоммитить релизные изменения и запушить ветку.
5. Запустить автоматические проверки из `.opencode/skills/checks-skill.md`.
6. Создать аннотированный тег `vX.Y.Z` на уже запушенном релизном коммите.
7. Запушить тег.
8. Проверить, что GitHub Actions собрал и опубликовал `.deb` в релизе.

Важно: тег создается только после коммита и push версии в `debian/changelog`.

## Команды

Запускать из корня проекта.

1) Проверка состояния репозитория:

```bash
git status --short --branch
git fetch --tags origin
git log --oneline --decorate -n 20
```

2) Анализ изменений с прошлого релиза:

```bash
git tag --sort=-creatordate
git log --oneline <prev_tag>..HEAD
```

Если тегов еще нет (первый стабильный релиз), анализировать всю историю:

```bash
git log --oneline --reverse
```

3) Обновление версии Debian-пакета:

```bash
dch --newversion 1.0.0-1 "First stable release."
```

Если `dch` недоступен, отредактировать `debian/changelog` вручную с тем же номером версии.

4) Проверки перед релизом:

- Выполнить все команды из `.opencode/skills/checks-skill.md`.

5) Коммит, push, тег:

```bash
git add CHANGELOG.md debian/changelog
git commit -m "Release 1.0.0"
git push origin master
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0
```

## Проверка согласованности версий

- `CHANGELOG.md` содержит секцию `## [1.0.0]`.
- `debian/changelog` верхняя запись имеет `move-reminder (1.0.0-1)`.
- Git-тег: `v1.0.0`.

## Критерий готовности

- Изменения закоммичены и запушены.
- Проверки из checks-skill пройдены.
- Создан и запушен тег `vX.Y.Z`.
- На GitHub-релизе присутствует собранный `.deb`.
