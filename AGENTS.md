# AGENTS

Этот файл задает правила для AI-агентов, которые вносят изменения в проект.

## Цель проекта

- `move-reminder` - простой tray-таймер для Ubuntu GNOME.
- Основной исполняемый файл: `timer_tray.py`.
- Запуск для разработки: `./run.sh`.

## Технический контекст

- Целевая платформа: Linux (Ubuntu 24.04, GNOME).
- Язык: Python 3.
- GUI и интеграции: `gi` (`Gtk`, `Notify`, `AyatanaAppIndicator3`).
- Проект упаковывается как Debian-пакет через `debian/`.

## Правила изменений

- Делай минимальные и точечные изменения без лишних рефакторингов.
- Сохраняй текущий стиль кода и структуру файлов.
- Не добавляй новые зависимости без явной необходимости.
- Не ломай сценарий запуска через `./run.sh`.
- Учитывай, что приложение должно работать в режиме одного экземпляра.

## Что проверять после правок

- Приложение запускается: `./run.sh`.
- Значок появляется в трее.
- Таймер стартует и корректно завершает отсчет.
- По завершении есть уведомление и звук (если доступен в системе).
- Также выполняй автоматические проверки из скилла: `.opencode/skills/checks-skill.md`.
- Для релиза используй порядок из `.opencode/skills/release-skill.md`.
- При любом изменении кода проверки обязательны.
- При добавлении функционала следи за актуальностью тестов: добавляй новые и обновляй существующие `pytest`-тесты.

## Правила релиза

- Релизный процесс описан в `.opencode/skills/release-skill.md`, следуй ему без перестановки шагов.
- Обязательная последовательность: `CHANGELOG.md` -> `debian/changelog` -> commit/push -> checks -> tag -> push tag.
- Для стабильного релиза приложения используй SemVer-тег `vX.Y.Z`.
- Версия Debian-пакета должна быть `X.Y.Z-1` для первого пакетного релиза этой версии.
- Если меняется только Debian-пакетирование без изменения версии приложения, увеличивай Debian revision: `X.Y.Z-2`, `X.Y.Z-3`.
- Не создавай и не пушь релизный тег, пока изменения версии не закоммичены и не запушены в `master`.

## Ограничения и безопасность

- Не добавляй в репозиторий секреты, токены или приватные ключи.
- Не меняй Debian-упаковку без необходимости.
- Не используй деструктивные git-команды (`reset --hard`, принудительные удаления и т.п.).

## Подсказки по внесению изменений

- При изменении поведения таймера обновляй `README.md`, если инструкции устарели.
- Если правки затрагивают запуск или окружение, синхронизируй `setup_dev.sh` и `run.sh`.
- Для UI-правок предпочитай простые и надежные решения, совместимые с GTK3.
